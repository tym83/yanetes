# Яндекснетес — дизайн (черновик)

«Kubernetes без Kubernetes». Снаружи `kubectl` и настоящий kubelet, внутри всё, что думает, написано заново: apiserver, хранилище, планировщик, контроллеры. Сквозные темы: свои велосипеды вместо готового, одержимость перформансом и масштабами «которых нет ни у кого», суперприложение с Плюсом в каждой щели.

Источники фактов: `research/tech.md` (стек), `research/lore.md` (лор). В статье подаём как факт только то, что там помечено FACT.

## Исследовательский вопрос

Сколько Kubernetes можно заменить своим кодом и открытым стеком Яндекса — и что после этого скажут конформанс и нагрузочные тесты. Обе цифры честные, какими бы они ни вышли.

## Архитектура

| Слой | Чем | Почему так |
|---|---|---|
| apiserver | **свой, C++ на userver** — `yapi` | главный велосипед; userver умеет HTTPS, HTTP/2, потоковые ответы (watch), JSON/YAML, кодогенерацию из OpenAPI и имеет встроенный драйвер YDB |
| хранилище | **YDB напрямую**, без etcd | раз apiserver свой, etcd-протокол не нужен: объекты в таблицах YDB, watch на changefeed, resourceVersion = виртуальный timestamp. Апстримный `etcd_proxy` из YDB держим как запасной путь и как предмет сравнения |
| планировщик | **свой, «как YP»** — `yplanner` | решение размещения как задача оптимизации; профиль «1922 фактора ранжирования» (число из утечки 2023) |
| контроллеры | **свои** — `nanny` | Deployment, ReplicaSet, Endpoints/EndpointSlice, Namespace, GC, ServiceAccount/токены, Node lifecycle — минимум, без которого кластер не живёт |
| kubelet, kube-proxy, CoreDNS, kubectl | **апстрим** | кубелет — граница эксперимента |
| рантайм | CRI-O/containerd, позже **Porto через portoshim** | portoshim жив, но на библиотеках k8s 1.26 — отдельная фаза с риском |
| узлы | VM на kuberoot в кластере воркшопов | как в Gachinetes; YDB требует AVX2 и ~80 ГБ диска — только там, не на маке |

Типы Kubernetes не пишем руками: схемы, дефолты и валидацию генерируем из апстримного OpenAPI. В статье это честно: «велосипед, но колёса заказали у них».

## Надстройки (сатира, работают поверх любого apiserver)

| Механика | Мем | В Kubernetes |
|---|---|---|
| Плюс | отмена в 8 экранов, баллы сгорят | финализатор `plus.yandex/subscription` на namespace: 8 стадий отговорок, на последней — «пробный период продлён»; priorityClass и кэшбэк баллами для подписчиков, реклама в логах для остальных |
| Найм | много секций, пауза полгода после отказа | узел и под проходят секции как readinessGates; алгоритмическая — настоящий прогон Танка; после всех этапов `Pending: TeamMatching`; отказ = backoff на «полгода» кластерного времени |
| Минусинск, Баден-Баден, АГС | поисковые фильтры | admission и ранжирование эндпоинтов на CatBoost: ссылочные фермы из Service, переспам лейблами, поды без трафика выпадают из выдачи; объяснения — только в `ya webmaster`, ответы подписывает Платон Щукин |
| Поиск по кластеру | реклама сверху, колдунщики | `ya get pods`: сначала рекламные поды, потом колдунщик, потом твои |
| Такси | повышенный спрос | surge-множитель на квоты и приоритет при нехватке узлов, класс узлов «Комфорт+» |
| Пробки, Лавка | баллы, 15 минут | состояние сети кластера в баллах 0–10; SLA на старт пода «за 15 минут» |
| SmartCaptcha | «запросы похожи на автоматические» | 429 с капчей, в том числе контроллерам; лимит по умолчанию — 21,8 млн RPS (Mēris) |
| Алиса | «регулятор хамства не убавить» | голосовой/чатовый `ya alice` вместо kubectl, флаг `--rudeness-level`, на правилах, без внешних нейросетей |
| Трекер и ABC | всё через тикет | изменение принимается, только если есть тикет и ОК ответственного |
| Реорганизации и ребрендинг | Такси → Go, Дзен → VK, N.V. → Nebius | kind'ы переименовываются через conversion webhook; ресурсы «продаются» соседнему кластеру; `ya split` делит кластер на две юрисдикции; Кью — namespace только для чтения |
| Элементы Яндекса | бар в нагрузку | каждый чарт тянет «Элементы» с галочкой, включённой по умолчанию |
| Велосипеды | Odyssey: «PR не приняли — написали своё» | NIH-метр: у каждого компонента страница «почему не взяли готовое» и счётчик строк с нуля |
| Имена релизов | Магадан → Находка → Снежинск | релизы называются городами по правилу последней буквы |

## Перформанс и масштаб

- `ya bench`: честная гонка `yapi`+YDB против kube-apiserver+etcd на одинаковой нагрузке (clusterloader2 / kube-burner + Танк). Каждая команда печатает, на сколько процентов быстрее «их Kubernetes». В README бейдж «в N раз быстрее*» и честная сноска.
- Масштаб через KWOK: 30 001 узел — на один больше самого большого кластера YP. Ошибки заканчиваются «на наших масштабах это нормально».
- Конформанс — KPI; всё непройденное получает ADR «нерелевантно для наших сценариев».

## Фазы

0. Каркас: репозиторий, сборочный образ userver, CI, YDB в кластере воркшопов.
1. Хранилище: схема в YDB, ревизии, watch через changefeed; бенч против etcd и против `etcd_proxy`.
2. `yapi` ядро: discovery, OpenAPI, CRUD + watch + list/pagination + селекторы + status-подресурс, merge/JSON patch; kubectl работает.
3. Аутентификация и авторизация: x509, токены ServiceAccount (TokenRequest), RBAC, bootstrap кубелета.
4. Контроллеры `nanny` и планировщик `yplanner`.
5. Настоящие узлы: kubelet на VM, первые поды, первый замер конформанса.
6. Server-side apply и strategic merge patch — самый тяжёлый кусок совместимости.
7. Надстройки (таблица выше).
8. Перформанс: `ya bench`, KWOK на 30 001 узел.
9. Porto через portoshim.
10. Конформанс до упора, статья.

## Открытые вопросы

- Язык надстроек: Go (быстрее писать, client-go) или тоже C++ «потому что у нас всё на плюсах»?
